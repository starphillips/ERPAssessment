.NET ERP Assessment

Starting point: Use the provided ERPAssessment Web API project. Complete all tasks inside the same application. Do not create separate projects for each task.

Scenario

You have joined a company that is building a small internal ERP system. The first version already stores employees, departments, roles and responsibilities. HR now wants you to improve it step by step.

The aim is not only to make the code work. Be ready to explain your decisions while you work.

15 XP

Task 1 — Improve the Employee Model

☐ Add validation so an employee cannot have a negative salary.
☐ Prevent an employee from being created with an empty name or email.
☐ Decide where this validation should live.

Explain: Why did you place the validation there?

Hint

Think about whether invalid data should be stopped in the controller, model, or service.

20 XP

Task 2 — Add Update and Delete

☐ Add PUT /api/employees/{id}.
☐ Add DELETE /api/employees/{id}.
☐ Return sensible HTTP status codes.

Explain: When would you return 200, 204, 400 and 404?

Hint

Think about what the API caller needs to know after each operation.

20 XP

Task 3 — Use OOP

The company now hires both permanent employees and contractors.

☐ Add PermanentEmployee and ContractEmployee.
☐ Add a way to calculate pay differently for each employee type.
☐ Use inheritance, abstraction or polymorphism where it makes sense.

Explain: What OOP principle did you use and why?

Hidden sample idea

A base employee type could expose a method such as CalculatePay(), with each employee type calculating it differently.

15 XP

Task 4 — Department Search

☐ Add an endpoint that returns employees for a department.
☐ Decide what the route should look like.

Explain: Why did you choose that route?

Hint

Examples could include a department id in the route or a query-string filter. Pick one and explain it.

20 XP

Task 5 — Debugging Challenge

Your mentor will introduce a small bug into the application.

☐ Reproduce the problem.
☐ Use breakpoints and inspect variables.
☐ Explain the root cause before fixing it.
☐ Fix the problem without breaking another endpoint.

Explain: What did you inspect, what did you expect, and what did you actually see?

10 XP

Final Discussion

Be ready to answer:

  • Why did you create separate Employee, Department and Role classes?
  • Why should salary use decimal rather than string?
  • Why is dependency injection useful?
  • What should happen if an employee is not found?
  • What would you change if this application used a real SQL database?
  • What part of your solution would you improve if you had another hour?
Mentor note: Give points for both implementation and explanation. A working solution with weak reasoning should not receive full marks.

Total: 100 XP
